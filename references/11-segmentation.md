# 集内分段与版本选择（单集超过单条上限时必读）

## 交付单位（重申，任何情况不得违反）

1 条提示词 = 用户在即梦点 1 次生成 = 一条完整时间轴，内含多个镜头。
**禁止逐镜输出提示词、禁止「逐镜单独生成后剪辑合成」类方案**——「单条 ≤15s」限的是一次生成的总时长，不是单个镜头的时长；每镜 2-5s 合规 ≠ 可以每镜出一条。

## 版本 × 拆条决策表（Phase 0 采访时完成，写进迷你方案给用户选）

| 单集实际时长 | 方案 |
|---|---|
| ≤15s | 2.0 一条 |
| 16-30s | 2.5 一条（用户更在意单条稳定性时可 2.0 两条） |
| >30s | 三选一并报代价：**2.0 拆 N 条**（N = ⌈时长÷15⌉，生成次数最多、单条最稳）／**2.5 拆 M 条**（M = ⌈时长÷30⌉，次数约减半）／**2.5 超长一条**（≤180s，次数最少、抽卡波动最大、废片需整集重生成） |

例：99s 的一集 = 2.0×7 条 / 2.5×4 条 / 2.5 超长×1 条。方案在迷你方案阶段给出对比，shot list gate 时最终拍板。

## 分段规则

- 分段点落在**节拍边界**，优先选场景切换或情绪断点；禁止切在动作中间——每段末镜必须结束在完成的动作 beat 上。
- 每段时间轴**从 0 重排**，各自独立成完整 8+1 区块提示词（风格串、人物、声音行、参考每段都要有——每段对即梦都是一次独立生成，不会继承上一段的任何上下文）。
- 段间衔接复用 references/07-series.md 的抽帧接力：上一段附尾帧五要素 → 下一段首镜与之逐项一致（同服装、同光线、同构图起点、同画面方向）。
- Phase 3 的 shot list 按段呈现（每段一张表，标注段号与段时长），用户确认的就是最终分段——不要先按整集排完再事后切。
- 交付时开头写明：「本集共 N 条提示词，需在即梦生成 N 次」，并逐条编号（1/N、2/N…）。

## 2.5 超长模式（路径二，仅用户明确选择时使用）

- 须满足 references/06-prompt-v25.md 超长模式附加要求：分幕、每幕一行幕旨、幕间用「场景切换」显式重建立、结尾有明确落点。
- 自检加 `--long`：`python3 scripts/check_prompt.py <文件> --duration <总秒数> --version 2.5 --long`。
- 必须主动提示代价：超长模式抽卡波动大，一条废了整集重抽；分段方案废一条只补一条。预算敏感或首次合作的用户建议分段。

## 每段编译后

逐段跑 check_prompt.py（`--duration` 传该段时长，不是整集时长），段段都过才交付。
